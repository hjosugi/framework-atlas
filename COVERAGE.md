# Coverage

Generated counts live in `data/stats.json` and are rendered on the static site.

Coverage is measured across independent axes:

- language
- problem domain/category
- project kind
- research depth (`deep`, `standard`, `seed`)
- relationship evidence state
- family-tree editorial coverage

A high repository count is not the same as high research quality. The dashboard therefore reports catalog records, deep profiles, verified relationship edges, hypotheses, and unresolved research questions separately.

A literal claim of permanent completeness is avoided. Dated GitHub topic snapshots, curated records, classification rules, and Issue backlogs make missing coverage observable and correctable.
