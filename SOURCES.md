# Source policy

Preferred sources, in order:

1. Official project design/history documentation
2. Maintainer-authored announcements, talks, interviews, and books
3. Primary papers or standards
4. Repository commits, release notes, and issue discussions
5. Foundation or vendor documentation
6. High-quality secondary histories

A project homepage proves identity and current positioning, but normally does not prove historical influence. A README that says “inspired by X” can support an influence edge. Similar APIs alone cannot.

All summaries in this repository are paraphrases. Source URLs and access dates are retained for verification.
