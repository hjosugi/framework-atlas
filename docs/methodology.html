Methodology

事実・仮説・分類を混ぜない

何を framework と呼ぶか

application structure と lifecycle を framework 側が制御するものを中核に置きます。library、runtime、router、toolkit、platform、application、network product、security tool は歴史的背景のため保持しますが、kind と category を分けます。

調査深度

deep は目的、成立史、設計、data model、tradeoff、一次資料を詳しく確認した record。standard は比較可能だが歴史や lineage に追加調査が残る record。seed は取りこぼし防止と Issue 生成のための候補です。

線の意味

実線は一次資料等で確認した関係、破線は追加 evidence が必要な influence / design response、点線は同じ問題領域・共通基盤・topic 分類です。似ている API だけで「影響を受けた」と断定しません。

GitHub Topics

GitHub topic は発見 signal であって taxonomy ではありません。router topic に HTTP routing、client navigation、network router firmware、VPN、security exploitation framework が混在するため、raw metadata と curated classification を分離します。

更新

raw snapshot は日付付きで保持し、curated record は pull request で review します。自動 collector は既存の解説と family tree を上書きしません。不足や source 消失は Issue にします。
